# 1. Basic Spring Boot Architecture

A common Spring Boot application follows this structure:

```text
              Client / Frontend
                     │
                     │ HTTP Request
                     ↓
              ┌──────────────┐
              │  Controller  │
              └──────┬───────┘
                     │
                     ↓
              ┌──────────────┐
              │   Service    │
              └──────┬───────┘
                     │
                     ↓
              ┌──────────────┐
              │  Repository  │
              └──────┬───────┘
                     │
                     ↓
              ┌──────────────┐
              │   Database   │
              └──────────────┘
```

---



# 2. Controller

The Controller handles incoming HTTP requests.

Example:

```java
@RestController
public class ProductController {

    @GetMapping("/products")
    public String getProducts() {
        return "Product List";
    }
}
```

If the frontend sends:

```text
GET /products
```

the request reaches the Controller.

### Simple definition

> Controller is responsible for receiving HTTP requests and returning HTTP responses.

---



# 3. Service

The Service contains the application's business logic.

Example:

```java
@Service
public class ProductService {

    public String getProduct() {
        return "Product";
    }
}
```

For example, business logic could be:

```text
Check product availability
Calculate price
Validate product
Calculate discount
Update stock
```



### Simple definition

> Service contains the business logic of the application.

---



# 4. Repository

The Repository is responsible for communicating with the database.

Example:

```java
@Repository
public class ProductRepository {
}
```

Conceptually:

```text
Service
   ↓
Repository
   ↓
Database
```



### Simple Real-World Example

Suppose we have a Product API.

Request:

```
GET /products/10
```

### Step 1 – Controller

Receives the request.

```
ProductController
```

### Step 2 – Service

Applies business logic.

```
ProductService
```

### Step 3 – Repository

Gets the data from the database.

```
ProductRepository
```

### Step 4 – Database

Returns the product.

```
PostgreSQL
```

Final flow:

```
GET /products/10
       ↓
Controller
       ↓
Service
       ↓
Repository
       ↓
PostgreSQL
       ↓
Response
```

# 5. Complete Request Flow

Suppose the frontend sends:

```text
GET /products/10
```

The flow is:

```text
Frontend
   ↓
ProductController
   ↓
ProductService
   ↓
ProductRepository
   ↓
PostgreSQL
   ↓
ProductRepository
   ↓
ProductService
   ↓
ProductController
   ↓
Response
   ↓
Frontend
```

This is the basic Spring Boot architecture you should understand for the interview.
