# MySQL CRUD, Schema Design and Relationships in Spring Boot (Java 11)

## Introduction

Most Spring Boot applications store data in a database.

A database helps us:
* Store data permanently
* Retrieve data when needed
* Update existing data
* Delete unwanted data

Spring Boot commonly uses **MySQL** as the database.

---

# What is MySQL?

MySQL is a Relational Database Management System (RDBMS). It stores data in tables.

## Users Table

| id | name   | email              |
| -- | ------ | ------------------ |
| 1  | Sakthi | sakthi@gmail.com   |
| 2  | John   | john@gmail.com     |

Each row is called a **Record**.
Each column is called a **Field**.

# Project Setup

Before writing code, you need to configure your Spring Boot project to connect to MySQL.

## 1. Maven Dependencies
Add these to your `pom.xml`:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-java</artifactId>
    <scope>runtime</scope>
</dependency>
```

## 2. application.properties
Configure your database connection credentials:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/mydb
spring.datasource.username=root
spring.datasource.password=root
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
# Optional but highly recommended for MySQL 8
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.MySQL8Dialect
```

# Entity Class

Entity represents a database table. Note the use of `javax.persistence.*` which is the standard for Java 11 / Spring Boot 2.x. *(If you are using Java 17+ / Spring Boot 3.x later on, simply replace `javax.persistence` with `jakarta.persistence`.)*

```java
import javax.persistence.*;

@Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private String email;

    // Getters and Setters
}
```

```java
}
```

# Service Layer (CRUD Operations)

The service layer handles the business logic and calls the repository. It is marked with `@Service` so Spring can inject it into the controller.

```java
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import java.util.List;

@Service
public class UserService {

    private final UserRepository userRepository;

    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    // --- CREATE Operation ---
    public User createUser(User user) {
        return userRepository.save(user);
    }

    // --- READ Operations ---
    public List<User> getUsers() {
        return userRepository.findAll();
    }

    public User getUser(Long id) {
        return userRepository.findById(id).orElse(null);
    }

    // --- UPDATE Operation ---
    @Transactional
    public User updateUser(Long id, User request) {
        User user = userRepository.findById(id)
                .orElseThrow(() -> new RuntimeException("User not found"));

        user.setName(request.getName());
        user.setEmail(request.getEmail());

        return userRepository.save(user);
    }

    // --- DELETE Operation ---
    @Transactional
    public void deleteUser(Long id) {
        userRepository.deleteById(id);
    }
}
```

# Controller Layer

The controller exposes your CRUD operations as REST API endpoints.

> **Best Practice Note:** In this tutorial, we are passing the `User` entity directly in our requests and responses to keep it simple. In real-world projects, you should avoid exposing entities directly. Instead, use **DTOs** (Data Transfer Objects), as covered in the standard Response Sending guide!

```java
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequestMapping("/users")
public class UserController {

    private final UserService userService;

    // Constructor Injection
    public UserController(UserService userService) {
        this.userService = userService;
    }

    @PostMapping
    public ResponseEntity<User> create(@RequestBody User user) {
        return ResponseEntity.status(201).body(userService.createUser(user));
    }

    @GetMapping
    public List<User> getAll() {
        return userService.getUsers();
    }

    @GetMapping("/{id}")
    public ResponseEntity<User> getOne(@PathVariable Long id) {
        User user = userService.getUser(id);
        if (user == null) {
            return ResponseEntity.notFound().build(); // 404 Not Found
        }
        return ResponseEntity.ok(user); // 200 OK
    }

    @PutMapping("/{id}")
    public User update(@PathVariable Long id, @RequestBody User user) {
        return userService.updateUser(id, user);
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(@PathVariable Long id) {
        userService.deleteUser(id);
        return ResponseEntity.noContent().build();
    }
}
```

# What is Schema Design?

Schema Design means planning how database tables should be structured.

Good schema design:
* Avoids duplicate data
* Improves performance
* Maintains data integrity
* Makes maintenance easier

---

# Poor vs. Better Schema Design

**Poor Schema (Data Duplication):**
Customer information repeats in every order row.
```text
Orders Table: order_id, customer_name, customer_email, product_name
```

**Better Schema (Normalized):**
Separate data into multiple tables.
```text
Customers: id, name, email
Orders: id, customer_id
Products: id, name, price
```

# Database Relationships

Tables often need connections, called Relationships.

1. One-to-One
2. One-to-Many
3. Many-to-Many

*Important Note on JSON Serialization:*
When entities reference each other, returning them in a REST API can cause **infinite recursion** (e.g., Customer loads Order, Order loads Customer...). You have two common ways to fix this:
1. `@JsonIgnore` - Hides the field completely from JSON.
2. `@JsonManagedReference` (Parent) & `@JsonBackReference` (Child) - Allows the parent to show the child list, but stops the child from looping back to the parent.

---

## 1. One-to-One Relationship

One user has one profile.

```java
@OneToOne(cascade = CascadeType.ALL)
@JoinColumn(name = "user_id")
private Profile profile;
```

---

## 2. One-to-Many Relationship

One customer can place many orders. 

### Customer Entity (Parent)
```java
import com.fasterxml.jackson.annotation.JsonManagedReference;

@OneToMany(mappedBy = "customer", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
@JsonManagedReference // Sends orders when fetching a customer
private List<Order> orders;
```
> **What is `mappedBy`?**
> `mappedBy` tells JPA that the `Order` entity owns the foreign key, so `Customer` should not create a duplicate connecting table or column.

### Order Entity (Child)
```java
import com.fasterxml.jackson.annotation.JsonBackReference;

@ManyToOne
@JoinColumn(name = "customer_id")
@JsonBackReference // Prevents infinite loop by not serializing customer inside order
private Customer customer;
```

---

## 3. Many-to-Many Relationship

A student can join many courses. A course can contain many students.

```text
Students Table -> Student_Course (Join Table) <- Courses Table
```

### JPA Mapping
```java
@ManyToMany(cascade = CascadeType.PERSIST, fetch = FetchType.LAZY)
@JoinTable(
        name = "student_course",
        joinColumns = @JoinColumn(name = "student_id"),
        inverseJoinColumns = @JoinColumn(name = "course_id")
)
@JsonIgnore
private List<Course> courses;
```
> **Why `CascadeType.PERSIST` instead of `ALL`?**
> `PERSIST` is chosen because calling a `REMOVE` operation on a many-to-many relationship with `CascadeType.ALL` can accidentally delete shared records across other entities (e.g., deleting a student might accidentally delete the course they are enrolled in for everyone else).

---

# Best Practices

* **Use Primary Keys:** Every table should have an `id BIGINT PRIMARY KEY`.
* **Use Foreign Keys:** Maintain relationships properly (e.g., `customer_id` references `customers.id`).
* **Avoid Duplicate Data:** Store data once and use relationships instead of repeating values.
* **Use Meaningful Table Names:** Use `users`, `orders`, `products` instead of `table1` or `data1`.
* **Normalize Data:** Split data into logical tables instead of using one huge table.
* **Control Cascades & Fetches:** Always define `CascadeType` and `FetchType` explicitly on relationships to optimize performance and prevent accidental data deletion.

## CRUD Operations & SQL Mapping

| Operation | Spring Data JPA Method | SQL Equivalent |
| --------- | ---------------------- | -------------- |
| Create    | `.save()`              | `INSERT`       |
| Read      | `.findAll()`, `.findById()`| `SELECT`   |

A well-designed schema with proper CRUD operations, correctly configured entity relationships, and robust controller endpoints makes Spring Boot applications scalable, maintainable, and easy to manage.
