# Response Sending in Spring Boot (Java 11)

## What is a Response?

A response is the data that a Spring Boot application sends back to the client after processing a request.

### Simple Flow

```text
Client Request
      |
      v
Spring Boot API
      |
      v
Process Request
      |
      v
Send Response
      |
      v
Client Receives Result
```

---

## Real-Life Example

A user requests order details.

### Request

```http
GET /orders/1001
```

### Response

```json
{
  "orderId": 1001,
  "customerName": "Sakthi",
  "status": "DELIVERED"
}
```

The API processes the request and sends the response back to the client.

---

# Types of Responses

Spring Boot can send different types of responses:

1. Plain Text Response
2. JSON Response
3. Custom Response Object
4. ResponseEntity Response
5. Error Response

---

# Plain Text Response

The controller returns a simple string.

```java
@RestController
@RequestMapping("/api")
public class UserController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello World";
    }
}
```

### Response

```text
Hello World
```

---

# JSON Response

Spring Boot automatically converts Java objects into JSON. **Under the hood, Spring automatically sets the `Content-Type: application/json` header.**

## User Class

```java
public class User {

    private Long id;
    private String name;

    // Default Constructor
    public User() {}

    // All-args Constructor
    public User(Long id, String name) {
        this.id = id;
        this.name = name;
    }

    // Getters and Setters
}
```

## Controller

```java
@GetMapping("/user")
public User getUser() {
    return new User(1L, "Sakthi");
}
```

### Response

```json
{
  "id": 1,
  "name": "Sakthi"
}
```

# Response DTO

In real projects, we usually send DTOs instead of entities.

## Response DTO

```java
public class UserResponse {

    private Long id;
    private String name;
    private String email;

    public UserResponse() {}

    public UserResponse(Long id, String name, String email) {
        this.id = id;
        this.name = name;
        this.email = email;
    }

    // Getters and Setters
}
```

## Controller

```java
@GetMapping("/users/1")
public UserResponse getUser() {
    UserResponse response = new UserResponse();
    
    response.setId(1L);
    response.setName("Sakthi");
    response.setEmail("sakthi@gmail.com");

    return response;
}
```

### Response

```json
{
  "id": 1,
  "name": "Sakthi",
  "email": "sakthi@gmail.com"
}
```

# ResponseEntity

`ResponseEntity` gives full control over:

* Response Body
* HTTP Status Code
* Headers

It is the most commonly used approach in Spring Boot APIs.

---

## Success Response

```java
@GetMapping("/success")
public ResponseEntity<String> success() {
    return ResponseEntity.ok("Request Successful");
}
```

### Response

```text
Request Successful
```

### HTTP Status

```text
200 OK
```

---

## Created Response

Used when a new resource is created. It is best practice to include a `Location` header pointing to the new resource.

```java
import java.net.URI;

@PostMapping("/users")
public ResponseEntity<String> createUser() {
    return ResponseEntity
            .created(URI.create("/users/1"))
            .body("User Created Successfully");
}
```

*(Alternative: You can also use `@ResponseStatus` instead of `ResponseEntity`)*
```java
@PostMapping("/users")
@ResponseStatus(HttpStatus.CREATED)
public UserResponse createUser() {
    // Save logic here...
    return new UserResponse(1L, "New User", "new@gmail.com");
}
```

### HTTP Status

```text
201 Created
```

---

## No Content Response

Very common for `DELETE` operations where the action succeeded but there is no data to return.

```java
@DeleteMapping("/users/{id}")
public ResponseEntity<Void> deleteUser(@PathVariable Long id) {
    // delete logic here
    return ResponseEntity.noContent().build(); 
}
```

### HTTP Status

```text
204 No Content
```

---

## Not Found Response

```java
@GetMapping("/users/{id}")
public ResponseEntity<String> getUser(@PathVariable Long id) {
    return ResponseEntity.status(404).body("User Not Found");
}
```

### HTTP Status

```text
404 Not Found
```

# Custom API Response Format

Most companies use a standard response structure so clients always know what format to expect.

## Response DTO

```java
public class ApiResponse<T> {

    private boolean success;
    private String message;
    private T data;

    public ApiResponse(boolean success, String message, T data) {
        this.success = success;
        this.message = message;
        this.data = data;
    }

    // Getters and Setters
}
```

---

## Success Response

```java
@GetMapping("/users/1")
public ResponseEntity<ApiResponse<UserResponse>> getUser() {

    UserResponse user = new UserResponse(1L, "Sakthi", "sakthi@gmail.com");

    ApiResponse<UserResponse> response = 
            new ApiResponse<>(true, "User Retrieved Successfully", user);

    return ResponseEntity.ok(response);
}
```

### Response

```json
{
  "success": true,
  "message": "User Retrieved Successfully",
  "data": {
    "id": 1,
    "name": "Sakthi",
    "email": "sakthi@gmail.com"
  }
}
```

# Error Response

When something goes wrong, returning a structured JSON error is much better than a plain string.

## Example

```java
@GetMapping("/users/{id}")
public ResponseEntity<ApiResponse<Void>> getUser(@PathVariable Long id) {

    if (id <= 0) {
        ApiResponse<Void> errorResponse = 
                new ApiResponse<>(false, "Invalid User Id", null);
                
        return ResponseEntity.badRequest().body(errorResponse);
    }

    return ResponseEntity.ok(new ApiResponse<>(true, "User Found", null));
}
```

### Error Response

```json
{
  "success": false,
  "message": "Invalid User Id",
  "data": null
}
```

### HTTP Status

```text
400 Bad Request
```

---

# Global Exception Response

Using `@RestControllerAdvice`. It is a best practice to catch **specific** exceptions (like `UserNotFoundException`) rather than generic `Exception.class`.

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(UserNotFoundException.class)
    public ResponseEntity<ApiResponse<Void>> handleUserNotFound(UserNotFoundException ex) {
        
        ApiResponse<Void> errorResponse = 
                new ApiResponse<>(false, ex.getMessage(), null);
                
        return ResponseEntity.status(404).body(errorResponse);
    }
}
```

### Response

```json
{
  "success": false,
  "message": "User with ID 10 not found in database",
  "data": null
}
```

# Best Practices

* Use DTOs for responses.
* Use `ResponseEntity` for better control over headers and status codes.
* Return proper HTTP status codes (`200`, `201`, `204`, `400`, `404`).
* Use meaningful messages in structured JSON error formats.
* Follow a standard API response format (like `ApiResponse<T>`).
* Catch specific exceptions globally using `@RestControllerAdvice`.
* Never expose internal database details directly.

---

# Summary

A response is the data sent back to the client after processing a request.

Common ways to send responses:

| Method           | Usage                                 |
| ---------------- | ------------------------------------- |
| `String`         | Simple text response                  |
| `Object`         | JSON response                         |
| `ResponseEntity` | Full control over response            |
| `Response DTO`   | Structured response                   |
| `ApiResponse<T>` | Standard company-wide response format |

In most Spring Boot projects, the preferred approach is:

```text
Controller
    |
    v
Response DTO
    |
    v
ResponseEntity
    |
    v
JSON Response
```

This approach creates clean, scalable, and professional REST APIs.
