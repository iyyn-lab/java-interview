# Response Sending in Spring Boot (Java 11)

## What is a Response?

A response is the data that a Spring Boot application sends back to the client after processing a request.

### Simple Flow

```text
Client Request
      |
      v
Spring Boot API
      |
      v
Process Request
      |
      v
Send Response
      |
      v
Client Receives Result
```

---

## Real-Life Example

A user requests order details.

### Request

```http
GET /orders/1001
```

### Response

```json
{
  "orderId": 1001,
  "customerName": "Sakthi",
  "status": "DELIVERED"
}
```

The API processes the request and sends the response back to the client.

---

# Types of Responses

Spring Boot can send different types of responses:

1. Plain Text Response
2. JSON Response
3. Custom Response Object
4. ResponseEntity Response
5. Error Response

---

# Plain Text Response

The controller returns a simple string.

```java
@RestController
@RequestMapping("/api")
public class UserController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello World";
    }
}
```

### Response

```text
Hello World
```

---

# JSON Response

Spring Boot automatically converts Java objects into JSON.

## User Class

```java
public class User {

    private Long id;
    private String name;

    // Constructors
    // Getters and Setters
}
```

## Controller

```java
@GetMapping("/user")
public User getUser() {

    return new User(
            1L,
            "Sakthi"
    );
}
```

### Response

```json
{
  "id": 1,
  "name": "Sakthi"
}
```

# Response DTO

In real projects, we usually send DTOs instead of entities.

## Response DTO

```java
public class UserResponse {

    private Long id;
    private String name;
    private String email;

    // Getters and Setters
}
```

## Controller

```java
@GetMapping("/users/1")
public UserResponse getUser() {

    UserResponse response = new UserResponse();

    response.setId(1L);
    response.setName("Sakthi");
    response.setEmail("sakthi@gmail.com");

    return response;
}
```

### Response

```json
{
  "id": 1,
  "name": "Sakthi",
  "email": "sakthi@gmail.com"
}
```

# ResponseEntity

`ResponseEntity` gives full control over:

* Response Body
* HTTP Status Code
* Headers

It is the most commonly used approach in Spring Boot APIs.

---

## Success Response

```java
@GetMapping("/success")
public ResponseEntity<String> success() {

    return ResponseEntity.ok("Request Successful");
}
```

### Response

```text
Request Successful
```

### HTTP Status

```text
200 OK
```

---

## Created Response

Used when a new resource is created.

```java
@PostMapping("/users")
public ResponseEntity<String> createUser() {

    return ResponseEntity.status(201)
            .body("User Created Successfully");
}
```

### HTTP Status

```text
201 Created
```

---

## Not Found Response

```java
@GetMapping("/users/{id}")
public ResponseEntity<String> getUser(
        @PathVariable Long id) {

    return ResponseEntity.status(404)
            .body("User Not Found");
}
```

### HTTP Status

```text
404 Not Found
```

# Sending Response with Object

```java
@GetMapping("/profile")
public ResponseEntity<UserResponse> profile() {

    UserResponse response = new UserResponse();

    response.setId(1L);
    response.setName("Sakthi");
    response.setEmail("sakthi@gmail.com");

    return ResponseEntity.ok(response);
}
```

### Response

```json
{
  "id": 1,
  "name": "Sakthi",
  "email": "sakthi@gmail.com"
}
```

# Custom API Response Format

Most companies use a standard response structure.

## Response DTO

```java
public class ApiResponse<T> {

    private boolean success;
    private String message;
    private T data;

    // Getters and Setters
}
```

---

## Success Response

```java
@GetMapping("/users/1")
public ResponseEntity<ApiResponse<UserResponse>> getUser() {

    UserResponse user = new UserResponse();
    user.setId(1L);
    user.setName("Sakthi");

    ApiResponse<UserResponse> response =
            new ApiResponse<>();

    response.setSuccess(true);
    response.setMessage("User Retrieved Successfully");
    response.setData(user);

    return ResponseEntity.ok(response);
}
```

### Response

```json
{
  "success": true,
  "message": "User Retrieved Successfully",
  "data": {
    "id": 1,
    "name": "Sakthi"
  }
}
```

# Error Response

When something goes wrong, the API should return meaningful error information.

## Example

```java
@GetMapping("/users/{id}")
public ResponseEntity<String> getUser(
        @PathVariable Long id) {

    if (id <= 0) {
        return ResponseEntity.badRequest()
                .body("Invalid User Id");
    }

    return ResponseEntity.ok("User Found");
}
```

### Error Response

```text
Invalid User Id
```

### HTTP Status

```text
400 Bad Request
```

---

# Global Exception Response

Using `@RestControllerAdvice`.

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public ResponseEntity<String> handleException(
            Exception ex) {

        return ResponseEntity.status(500)
                .body("Something Went Wrong");
    }
}
```

### Response

```text
Something Went Wrong
```

# Best Practices

* Use DTOs for responses.
* Use `ResponseEntity` for better control.
* Return proper HTTP status codes.
* Use meaningful messages.
* Follow a standard API response format.
* Handle exceptions globally.
* Never expose internal database details directly.

---

# Summary

A response is the data sent back to the client after processing a request.

Common ways to send responses:

| Method           | Usage                                 |
| ---------------- | ------------------------------------- |
| `String`         | Simple text response                  |
| `Object`         | JSON response                         |
| `ResponseEntity` | Full control over response            |
| `Response DTO`   | Structured response                   |
| `ApiResponse<T>` | Standard company-wide response format |

In most Spring Boot projects, the preferred approach is:

```text
Controller
    |
    v
Response DTO
    |
    v
ResponseEntity
    |
    v
JSON Response
```

This approach creates clean, scalable, and professional REST APIs.
