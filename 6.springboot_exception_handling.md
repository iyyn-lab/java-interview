# Spring Boot Exception Handling

Exception handling is used to handle errors that occur while a Spring Boot application is running.

Instead of returning unclear or technical errors to the client, we can handle exceptions and return a proper response.

---

# 1. What is an Exception?

An exception is an unexpected problem that occurs while the application is running.

For example:

```text
Client
   ↓
GET /products/100
   ↓
Product does not exist
   ↓
Exception
```

Without proper exception handling, the client may receive an unclear error response.

With exception handling:

```json
{
  "status": 404,
  "message": "Product not found"
}
```



### Common Examples

```text
Product not found
Invalid request
Invalid input
Database error
Unauthorized access
Resource already exists
```

---



# 2. Why Exception Handling is Important

Exception handling helps to:

- Return meaningful error messages
- Return correct HTTP status codes
- Avoid exposing internal application details
- Keep error responses consistent
- Make debugging easier
- Centralize error handling

Example:

```text
Without handling:

500 Internal Server Error
Some technical error...


With handling:

404 NOT FOUND
Product not found
```

# 3. try-catch in Java

Java provides `try-catch` for handling exceptions.

Example:

```java
public void getProduct() {

    try {
        // Code that may throw an exception
        int result = 10 / 0;

    } catch (ArithmeticException exception) {
        System.out.println("Something went wrong");
    }
}
```

The `try` block contains code that may cause an exception.

The `catch` block handles the exception.

```text
try
 ↓
Exception occurs
 ↓
catch
 ↓
Handle the exception
```

# 4. Spring Boot Exception Handling

Spring Boot provides annotations that make exception handling easier.

Important annotations:

```text
@ExceptionHandler
@ControllerAdvice
@RestControllerAdvice
@ResponseStatus
```

For REST APIs, `@RestControllerAdvice` is commonly used for global exception handling.

---



# 5. @ExceptionHandler

`@ExceptionHandler` is used to handle a specific exception.

Example:

```java
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ProductNotFoundException.class)
    public String handleProductNotFound(
            ProductNotFoundException exception) {

        return exception.getMessage();
    }
}
```

If `ProductNotFoundException` occurs, this method handles it.

Flow:

```text
Exception occurs
       ↓
@ExceptionHandler
       ↓
Handle exception
       ↓
Return response
```

# 6. Custom Exception

We can create our own exception for business-specific errors.

Example:

```java
public class ProductNotFoundException extends RuntimeException {

    public ProductNotFoundException(String message) {
        super(message);
    }
}
```

Now we can throw it when a product does not exist.

```java
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    public String getProduct(Long productId) {

        boolean productExists = false;

        if (!productExists) {
            throw new ProductNotFoundException(
                    "Product not found"
            );
        }

        return "Product";
    }
}
```

The custom exception represents a specific business error.

```text
Product does not exist
       ↓
ProductNotFoundException
```

# 7. Global Exception Handling

In a real application, we may have many Controllers.

Instead of handling exceptions separately in every Controller, we can create one common exception handler.

```text
ProductController ─┐
                    │
OrderController ───┼──→ Global Exception Handler
                    │
UserController ────┘
```

This is called **Global Exception Handling**.

---



# 8. @RestControllerAdvice

`@RestControllerAdvice` is commonly used for global exception handling in REST APIs.

Example:

```java
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ProductNotFoundException.class)
    public String handleProductNotFound(
            ProductNotFoundException exception) {

        return exception.getMessage();
    }
}
```

Now the exception can be handled globally.

### Remember

> `@RestControllerAdvice` provides centralized exception handling for REST Controllers.

---



# 9. @ControllerAdvice

`@ControllerAdvice` also provides global exception handling.

Example:

```java
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.bind.annotation.ExceptionHandler;

@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public String handleException(Exception exception) {
        return "Something went wrong";
    }
}
```

For REST APIs, `@RestControllerAdvice` is commonly preferred because it automatically handles the response body.

---



# 10. Returning HTTP Status

An API should return the appropriate HTTP status along with the error message.

One simple approach is `ResponseEntity`.

Example:

```java
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ProductNotFoundException.class)
    public ResponseEntity<String> handleProductNotFound(
            ProductNotFoundException exception) {

        return ResponseEntity
                .status(HttpStatus.NOT_FOUND)
                .body(exception.getMessage());
    }
}
```

Response:

```text
HTTP 404 NOT FOUND

Product not found
```

---



# 11. Error Response Object

In production applications, instead of returning only a String, we can return a structured error response.

Example:

```java
public class ErrorResponse {

    private int status;
    private String message;

    public ErrorResponse(int status, String message) {
        this.status = status;
        this.message = message;
    }

    public int getStatus() {
        return status;
    }

    public String getMessage() {
        return message;
    }
}
```

The exception handler can return this object.

```java
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ProductNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleProductNotFound(
            ProductNotFoundException exception) {

        ErrorResponse response = new ErrorResponse(
                404,
                exception.getMessage()
        );

        return ResponseEntity
                .status(HttpStatus.NOT_FOUND)
                .body(response);
    }
}
```

The API response can look like:

```json
{
  "status": 404,
  "message": "Product not found"
}
```

# 12. @ResponseStatus

`@ResponseStatus` can be used to associate an HTTP status with an exception.

Example:

```java
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.ResponseStatus;
```

@ResponseStatus(HttpStatus.NOT_FOUND)
public class ProductNotFoundException extends RuntimeException {

```
public ProductNotFoundException(String message) {
    super(message);
}
```

}

When this exception occurs:

```text
ProductNotFoundException
        ↓
HTTP 404 NOT FOUND
```

This is a simple approach for exceptions that always map to the same HTTP status.

# 13. Handling Multiple Exceptions

A global exception handler can handle different exception types.

Example:

```java
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ProductNotFoundException.class)
    public ResponseEntity<String> handleProductNotFound(
            ProductNotFoundException exception) {

        return ResponseEntity
                .status(HttpStatus.NOT_FOUND)
                .body(exception.getMessage());
    }

    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<String> handleInvalidInput(
            IllegalArgumentException exception) {

        return ResponseEntity
                .status(HttpStatus.BAD_REQUEST)
                .body(exception.getMessage());
    }
}
```

Now:

```text
ProductNotFoundException
        ↓
404 NOT FOUND


IllegalArgumentException
        ↓
400 BAD REQUEST
```

---



# 14. Generic Exception Handling

We can also handle unexpected exceptions.

Example:

```java
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public ResponseEntity<String> handleGeneralException(
            Exception exception) {

        return ResponseEntity
                .status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body("Something went wrong");
    }
}
```

This can act as a fallback for unexpected exceptions.

However, applications should normally handle known business exceptions separately so that clients receive useful and accurate responses.

A typical REST API exception flow looks like:

```text
Client
   ↓
Controller
   ↓
Service
   ↓
Exception occurs
   ↓
Global Exception Handler
   ↓
HTTP Status + Error Response
   ↓
Client
```

Example:

```text
GET /products/100
        ↓
ProductController
        ↓
ProductService
        ↓
Product not found
        ↓
ProductNotFoundException
        ↓
@RestControllerAdvice
        ↓
404 NOT FOUND
```

# 16. Controller + Service + Exception Example



### Controller

```java
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class ProductController {

    private final ProductService productService;

    public ProductController(ProductService productService) {
        this.productService = productService;
    }

    @GetMapping("/products/{id}")
    public String getProduct(@PathVariable Long id) {
        return productService.getProduct(id);
    }
}
```



### Service

```java
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    public String getProduct(Long id) {

        boolean productExists = false;

        if (!productExists) {
            throw new ProductNotFoundException(
                    "Product not found"
            );
        }

        return "Product";
    }
}
```



### Exception

```java
public class ProductNotFoundException extends RuntimeException {

    public ProductNotFoundException(String message) {
        super(message);
    }
}
```



### Global Handler

```java
import org.springframework.http.HttpStatus;

import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

}
```

Complete flow:

```text

       ↓

       ↓
```

# 17. Best Practices

For a production Spring Boot application:

### 1. Use meaningful custom exceptions

```text
ProductNotFoundException
UserNotFoundException
OrderNotFoundException
```

Instead of using generic exceptions everywhere.

### 2. Use global exception handling

Keep common error handling in one place.

```text
@RestControllerAdvice
```



### 3. Return proper HTTP status codes

For example:

```text
400 → Invalid request
401 → Not authenticated
403 → Not allowed
404 → Resource not found
409 → Conflict
500 → Unexpected server error
```



### 4. Don't expose internal details

Avoid returning things like:

```text
Database password
SQL query
Internal stack trace
Server configuration
```

to the client.

### 5. Log unexpected errors

Logging can help developers investigate production issues.

```text
Exception
   ↓
Log error
   ↓
Return safe error response
```

# 19. Interview Quick Revision



### What is Exception Handling?

> Exception handling is the process of handling application errors and returning appropriate responses instead of exposing unexpected errors to the client.



### What is `@ExceptionHandler`?

> `@ExceptionHandler` is used to handle a specific exception in a Controller or advice class.



### What is `@RestControllerAdvice`?

> `@RestControllerAdvice` provides centralized exception handling for REST APIs.



### What is `@ControllerAdvice`?

> `@ControllerAdvice` provides common functionality, including exception handling, across multiple Controllers.



### Why use custom exceptions?

> Custom exceptions represent specific application or business errors clearly.



### Why use `ResponseEntity`?

> `ResponseEntity` allows us to control the HTTP status, headers, and response body.
