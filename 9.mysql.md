# MySQL CRUD, Schema Design and Relationships in Spring Boot (Java 11)

## Introduction

Most Spring Boot applications store data in a database.

A database helps us:

* Store data permanently
* Retrieve data when needed
* Update existing data
* Delete unwanted data

Spring Boot commonly uses **MySQL** as the database.

---

# What is MySQL?

MySQL is a Relational Database Management System (RDBMS).

It stores data in tables.

Example:

## Users Table

| id | name   | email                                       |
| -- | ------ | ------------------------------------------- |
| 1  | Sakthi | [sakthi@gmail.com](mailto:sakthi@gmail.com) |
| 2  | John   | [john@gmail.com](mailto:john@gmail.com)     |

Each row is called a **Record**.

Each column is called a **Field**.

---

# What is CRUD?

CRUD represents the four basic database operations.

| Operation | Meaning              |
| --------- | -------------------- |
| Create    | Insert new data      |
| Read      | Retrieve data        |
| Update    | Modify existing data |
| Delete    | Remove data          |

---

# CRUD Flow

```text

      |
      v

      |

      v

      v
MySQL Database
```

# Entity Class

Entity represents a database table.

```java
import jakarta.persistence.*;

@Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    private String email;

    // Getters and Setters
}
```

---

# Repository Layer

Spring Data JPA provides CRUD methods automatically.

```java
import org.springframework.data.jpa.repository.JpaRepository;

public interface UserRepository
        extends JpaRepository<User, Long> {
}
```

---

# CREATE Operation

Insert new data into the database.

## Service

```java
public User createUser(User user) {
    return userRepository.save(user);
}
```

## SQL Behind the Scenes

```sql
INSERT INTO users(name, email)
VALUES ('Sakthi', 'sakthi@gmail.com');
```

---

# READ Operation

Retrieve data from the database.

## Get All Users

```java
public List<User> getUsers() {
    return userRepository.findAll();
}
```

## SQL Behind the Scenes

```sql
SELECT * FROM users;
```

---

## Get User By Id

```java
public User getUser(Long id) {
    return userRepository.findById(id)
            .orElse(null);
}
```

## SQL Behind the Scenes

```sql
SELECT * FROM users
WHERE id = 1;
```

---

# UPDATE Operation

Modify existing data.

```java
public User updateUser(Long id,
                       User request) {

    User user =
            userRepository.findById(id)
                    .orElseThrow();

    user.setName(request.getName());
    user.setEmail(request.getEmail());

    return userRepository.save(user);
}
```

## SQL Behind the Scenes

```sql
UPDATE users
SET name = 'Updated Name'
WHERE id = 1;
```

---

# DELETE Operation

Remove data from database.

```java
public void deleteUser(Long id) {
    userRepository.deleteById(id);
}
```

## SQL Behind the Scenes

```sql
DELETE FROM users
WHERE id = 1;
```

# What is Schema Design?

Schema Design means planning how database tables should be structured.

Good schema design:

* Avoids duplicate data
* Improves performance
* Maintains data integrity
* Makes maintenance easier

---

# Poor Schema Example

```text
Orders Table

order_id
customer_name
customer_email
customer_phone
product_name
product_price
```

Problem:

Customer information repeats in every order.

```text
Order 1 -> Sakthi
Order 2 -> Sakthi
Order 3 -> Sakthi
```

Duplicate data wastes storage.

---

# Better Schema Design

Separate data into multiple tables.

```text
Customers
---------
id
name
email

Orders
---------
id
customer_id

Products
---------
id
name
price
```

Benefits:

* Less duplication
* Easier updates
* Better scalability

# Database Relationship Overview

Tables often need connections.

These connections are called Relationships.

Three common relationships:

1. One-to-One
2. One-to-Many
3. Many-to-Many

---

# One-to-One Relationship

One record is linked to one record.

Example:

```text
User
  |
  |
  v
Profile
```

A user has one profile.

A profile belongs to one user.

---

## Database Tables

```text
Users
-----
id
name

Profiles
--------
id
address
user_id
```

---

## JPA Mapping

```java
@OneToOne
@JoinColumn(name = "user_id")
private Profile profile;
```

---

# One-to-Many Relationship

One parent can have many children.

Example:

```text
Customer
    |
    |
    +---- Order 1
    |
    +---- Order 2
    |
    +---- Order 3
```

One customer can place many orders.

---

## Database Tables

```text
Customers
---------
id
name

Orders
------
id
customer_id
```

---

## JPA Mapping

Customer:

```java
@OneToMany(mappedBy = "customer")
private List<Order> orders;
```

Order:

```java
@ManyToOne
@JoinColumn(name = "customer_id")
private Customer customer;
```

---

# Many-to-One Relationship

Many records belong to one parent.

Example:

```text
Order 1
Order 2
Order 3
    |
    |
    v
Customer
```

Many orders belong to one customer.

---

## JPA Mapping

```java
@ManyToOne
@JoinColumn(name = "customer_id")
private Customer customer;
```

---

# Many-to-Many Relationship

Many records can relate to many records.

Example:

```text
Students
    |
    |
Many-to-Many
    |
    |
Courses
```

A student can join many courses.

A course can contain many students.

---

# Join Table

```text
Students
--------
id
name

Courses
--------
id
name

Student_Course
--------------
student_id
course_id
```

---

## JPA Mapping

```java
@ManyToMany
@JoinTable(
        name = "student_course",
        joinColumns =
        @JoinColumn(name = "student_id"),
        inverseJoinColumns =
        @JoinColumn(name = "course_id")
)
private List<Course> courses;
```

# Best Practices

## Use Primary Keys

Every table should have:

```sql
id BIGINT PRIMARY KEY
```

---

## Use Foreign Keys

Maintain relationships properly.

```sql
customer_id
```

should reference

```sql
customers.id
```

---

## Avoid Duplicate Data

Store data once.

Use relationships instead of repeating values.

---

## Use Meaningful Table Names

Good:

```text
users
orders
products
complaints
```

Avoid:

```text
table1
data1
abc
```

---

## Normalize Data

Split data into logical tables.

Example:

```text
Customer Table
Order Table
Product Table
```

instead of one huge table.
