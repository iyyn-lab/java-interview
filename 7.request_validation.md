# Request Validation in Spring Boot (Java 11)

## What is Request Validation?

Request Validation is the process of checking whether the data sent by the client is valid before processing it.

### Why Do We Need Validation?

Without validation, users can send:

* Empty values
* Invalid email addresses
* Negative prices
* Incorrect phone numbers
* Missing required fields

Validation helps ensure that only valid data enters the application.

---

## Project Setup

To use Bean Validation in Spring Boot 2.x (Java 11), you must include the following dependency in your `pom.xml`:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

## Real-Life Example

Imagine an e-commerce application where a user creates an account.

The API expects:

```json
{
  "name": "John",
  "email": "john@gmail.com",
  "age": 25
}
```

### Valid Request

```json
{
  "name": "John",
  "email": "john@gmail.com",
  "age": 25
}
```

The request is accepted.

### Invalid Request

```json
{
  "name": "",
  "email": "abc",
  "age": -5
}
```

Problems:
* Name is empty
* Email format is invalid
* Age is negative

The request should be rejected.

# Common Validation Annotations

Spring Boot uses Bean Validation annotations.

### 💡 Quick Comparison: Null vs Empty vs Blank
* **`@NotNull`**: Field cannot be null (but can be empty or just spaces).
* **`@NotEmpty`**: Field cannot be null AND length must be > 0 (but can be just spaces).
* **`@NotBlank`**: Field cannot be null AND must contain at least one non-whitespace character.

## @NotNull
Field cannot be null.
```java
@NotNull
private String name;
```

## @NotBlank
Field cannot be null, empty, or spaces only.
```java
@NotBlank
private String name;
```

## @NotEmpty
Used for String, List, Set, or Array. Cannot be empty.
```java
@NotEmpty
private List<String> skills;
```

## @Size
Checks minimum and maximum length.
```java
@Size(min = 3, max = 20)
private String username;
```

## @Email
Validates email format.
```java
@Email
private String email;
```

## @Min
Minimum value allowed.
```java
@Min(18)
private Integer age;
```

## @Max
Maximum value allowed.
```java
@Max(100)
private Integer age;
```

## @Pattern
Used for custom validation using Regular Expressions. Example: 10-digit mobile number.
```java
@Pattern(regexp = "^[0-9]{10}$")
private String mobileNumber;
```

# DTO with Validation

```java
import javax.validation.constraints.*;

public class UserRequest {

    @NotBlank(message = "Name is required")
    private String name;

    @Email(message = "Enter a valid email")
    private String email;

    @Min(value = 18, message = "Age must be at least 18")
    private Integer age;

    // Getters and Setters
}
```

# Using @Valid in Controller

Spring performs validation when `@Valid` is used. 

```java
import javax.validation.Valid;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/users")
public class UserController {

    @PostMapping
    public ResponseEntity<String> createUser(
            @Valid @RequestBody UserRequest request) {

        return ResponseEntity.ok("User Created");
    }
}
```

> **Note on `@Validated`:** If you need to validate individual `@RequestParam` or `@PathVariable` arguments, you must add the `@Validated` annotation at the **class level** of your controller.

# Global Exception Handling

Use `@RestControllerAdvice` to return clean validation errors. Instead of returning a generic error, parsing the `BindingResult` allows you to return specific field-level messages.

```java
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.HashMap;
import java.util.Map;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, String>> handleValidationException(
            MethodArgumentNotValidException ex) {
            
        Map<String, String> errors = new HashMap<>();
        
        ex.getBindingResult().getFieldErrors().forEach(err ->
            errors.put(err.getField(), err.getDefaultMessage())
        );
        
        return ResponseEntity.badRequest().body(errors);
    }
}
```

### Validation Error Response Example

If a client sends an invalid request, the exception handler above intercepts it and returns a `400 Bad Request` with a helpful JSON response:

```json
{
  "name": "Name is required",
  "email": "Enter a valid email",
  "age": "Age must be at least 18"
}
```

# Best Practices
* Always validate user input.
* Use DTOs instead of entity classes for requests.
* Use `@Valid` in controllers.
* Provide meaningful error messages.
* Use global exception handling for consistent responses.
* Never trust client input directly.

---

# Summary

Request Validation ensures that incoming API data is correct before processing. It is implemented using Validation annotations in DTOs, `@Valid` in Controller methods, and Global Exception Handling for errors. 

### Annotation Summary

| Annotation  | Purpose                                 |
| ----------- | --------------------------------------- |
| `@NotNull`  | Value cannot be null                    |
| `@NotBlank` | String cannot be null, empty, or spaces |
| `@NotEmpty` | Collection/String cannot be empty       |
| `@Size`     | Minimum and maximum length              |
| `@Email`    | Valid email format                      |
| `@Min`      | Minimum value                           |
| `@Max`      | Maximum value                           |
| `@Pattern`  | Custom validation rule using regex      |

This helps build secure, reliable, and user-friendly APIs.
