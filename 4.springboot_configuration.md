# Spring Boot – Core Concepts Interview Notes

> Beginner-friendly notes for Java 11 + Spring Boot interview preparation.

---

# 1. Spring Boot Architecture

A typical Spring Boot application is divided into different layers.

```text
Client / Frontend
       ↓
   Controller
       ↓
     Service
       ↓
   Repository
       ↓
    Database
```

## Controller

The Controller receives HTTP requests from the client.

Example:

```java
@RestController
public class ProductController {

    @GetMapping("/products")
    public String getProducts() {
        return "Product List";
    }
}
```

```text
GET /products
      ↓
ProductController
      ↓
Response
```

### Remember

> Controller handles HTTP requests and responses.

---

## Service

The Service contains business logic.

Example:

```java
@Service
public class ProductService {

    public String getProduct() {
        return "Product";
    }
}
```

Business logic can include:

```text
Check stock
Calculate price
Validate product
Calculate discount
```

### Remember

> Service contains business logic.

---

## Repository

The Repository communicates with the database.

```text
Service
   ↓
Repository
   ↓
Database
```

Example:

```java
@Repository
public class ProductRepository {
}
```

### Remember

> Repository handles database-related operations.

---

## Complete Request Flow

For example:

```text
GET /products/10
       ↓
Controller
       ↓
Service
       ↓
Repository
       ↓
Database
       ↓
Response
```

This separation makes the application easier to maintain and test.

# 2. Dependency Injection (DI)

Dependency Injection is one of the most important concepts in Spring.

## What is a Dependency?

Suppose `ProductController` needs `ProductService`.

```text
ProductController
       ↓
needs
       ↓
ProductService
```

`ProductService` is a dependency of `ProductController`.

---

## Without Dependency Injection

The Controller creates the Service itself:

```java
ProductService service = new ProductService();
```

Now the Controller is responsible for creating the dependency.

---

## With Dependency Injection

Spring creates the required object and provides it to the Controller.

```java
@RestController
public class ProductController {

    private final ProductService productService;

    public ProductController(ProductService productService) {
        this.productService = productService;
    }
}
```

Spring sees that `ProductController` needs `ProductService` and injects it.

```text
Spring Container
      ↓
Creates ProductService
      ↓
Injects it into ProductController
```

### Simple Definition

> Dependency Injection means providing the required dependency to a class instead of the class creating the dependency itself.

---

## Constructor Injection

The example above is called **Constructor Injection**.

```java
public ProductController(ProductService productService) {
    this.productService = productService;
}
```

Constructor injection is commonly preferred because dependencies are clearly defined when the object is created.

---

## Spring Container

The Spring Container manages Spring objects called **Beans**.

```text
Spring Container
      │
      ├── ProductController Bean
      ├── ProductService Bean
      ├── ProductRepository Bean
      └── Other Beans
```

Spring manages these objects and their dependencies.

---

# 3. Spring Boot Annotations

Annotations start with `@`.

Examples:

```text
@Controller
@RestController
@Service
@Repository
@Autowired
@Bean
@Configuration
```

Annotations tell Spring how a class or method should behave.

---

# 3.1 @Controller

`@Controller` marks a class as a Spring MVC Controller.

It is generally used for handling web requests and can return views.

```java
@Controller
public class ProductController {
}
```

### Remember

> `@Controller` is used to define a Controller in a Spring application.

---

# 3.2 @RestController

`@RestController` is commonly used for REST APIs.

```java
@RestController
public class ProductController {

    @GetMapping("/products")
    public String getProducts() {
        return "Product List";
    }
}
```

The response is returned directly to the client.

```text
GET /products
      ↓
@RestController
      ↓
"Product List"
```

### Important

`@RestController` is effectively:

```text
@Controller
+
@ResponseBody
```

### Remember

> Use `@RestController` when building REST APIs.

---

# 3.3 @Service

`@Service` marks a class as a service/business-logic component.

```java
@Service
public class ProductService {

    public String getProduct() {
        return "Product";
    }
}
```

Spring detects it and manages it as a Bean.

### Remember

> `@Service` is used for business logic.

---

# 3.4 @Repository

`@Repository` marks a class as a repository/data-access component.

```java
@Repository
public class ProductRepository {
}
```

It is generally responsible for database operations.

### Remember

> `@Repository` is used for data/database access.

---

# 3.5 @Autowired

`@Autowired` tells Spring to inject a dependency.

Example:

```java
@RestController
public class ProductController {

    @Autowired
    private ProductService productService;
}
```

Spring provides the `ProductService` object.

However, constructor injection is commonly preferred:

```java
@RestController
public class ProductController {

    private final ProductService productService;

    public ProductController(ProductService productService) {
        this.productService = productService;
    }
}
```

### Remember

> `@Autowired` is used for Dependency Injection.

---

# 3.6 @Bean

`@Bean` tells Spring to create and manage an object as a Bean.

Example:

```java
@Configuration
public class AppConfig {

    @Bean
    public ProductService productService() {
        return new ProductService();
    }
}
```

Now Spring manages the returned `ProductService` object.

### When is @Bean useful?

It is useful when we need to configure or create an object manually.

For example:

```text
Third-party library object
Custom configuration object
Special application object
```

### Remember

> `@Bean` tells Spring to manage the object returned by a method.

---

# 3.7 @Configuration

`@Configuration` marks a class as a configuration class.

Example:

```java
@Configuration
public class AppConfig {

    @Bean
    public ProductService productService() {
        return new ProductService();
    }
}
```

Usually:

```text
@Configuration
      ↓
@Bean
      ↓
Spring-managed object
```

### Remember

> `@Configuration` is used to define application configuration and Beans.

---

# 4. Spring Boot Configuration

Spring Boot applications need configuration values.

Examples:

```text
Server Port
Database URL
Database Username
Database Password
External API URL
Logging Level
```

These can commonly be stored in:

```text
application.properties
```

or:

```text
application.yml
```

---

## application.properties

Example:

```properties
server.port=8080

spring.datasource.url=jdbc:postgresql://localhost:5432/mydb
spring.datasource.username=postgres
spring.datasource.password=password
```

The application can use these values instead of hardcoding them in Java code.

---

## application.yml

The same type of configuration can also be written using YAML.

```yaml
server:
  port: 8080
```

Both approaches are commonly used.

---

## Why Configuration?

Instead of writing:

```java
String url = "http://localhost:3000";
```

we can keep it in configuration:

```properties
app.frontend-url=http://localhost:3000
```

This makes it easier to change values between environments.

```text
Development
     ↓
Configuration

Testing
     ↓
Configuration

Production
     ↓
Configuration
```

### Remember

> Configuration allows application settings to be managed outside the main business logic.

---

# 5. Logging and Monitoring

## Logging

Logging helps us understand what is happening inside an application.

For example:

```text
Application started
Product created
User logged in
Database connection failed
API request failed
```

A simple example:

```java
log.info("Product created successfully");
```

For errors:

```java
log.error("Failed to create product");
```

Common log levels:

```text
TRACE
DEBUG
INFO
WARN
ERROR
```

### Simple meaning

```text
INFO  → Normal application information
DEBUG → Debugging information
WARN  → Something may need attention
ERROR → Something failed
```

---

# Monitoring

Monitoring helps us understand the health and performance of an application.

We may monitor:

```text
Application Health
CPU
Memory
API Requests
Response Time
Errors
Database Health
```

Spring Boot commonly uses **Spring Boot Actuator** for monitoring and production-related information.

For example:

```text
/actuator/health
```

can provide application health information.

Example:

```json
{
  "status": "UP"
}
```

### Remember

> Logging tells us what is happening; monitoring helps us understand the health and performance of the application.

# 6. Exception Handling

An Exception represents an unexpected problem during application execution.

For example:

```text
GET /products/100
        ↓
Product 100 does not exist
        ↓
Exception
```

Instead of returning an unclear error, we should return a meaningful response.

Example:

```json
{
  "status": 404,
  "message": "Product not found"
}
```

---

# @ExceptionHandler

`@ExceptionHandler` can be used to handle a specific exception.

Example:

```java
@ExceptionHandler(ProductNotFoundException.class)
public String handleProductNotFound() {
    return "Product not found";
}
```

### Remember

> `@ExceptionHandler` is used to handle exceptions in Spring applications.

---

# @ControllerAdvice

`@ControllerAdvice` allows exception handling to be shared across multiple Controllers.

Example:

```java
@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public String handleException() {
        return "Something went wrong";
    }
}
```

Instead of writing exception handling separately in every Controller, we can have a common handler.

---

# @RestControllerAdvice

`@RestControllerAdvice` is commonly used for REST APIs.

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public String handleException() {
        return "Something went wrong";
    }
}
```

It is useful for returning structured API error responses.

---

# Simple Exception Flow

```text
Controller
    ↓
Service
    ↓
Exception occurs
    ↓
Global Exception Handler
    ↓
Proper HTTP Response
```

Example:

```text
Product not found
       ↓
404 NOT FOUND
       ↓
{
  "message": "Product not found"
}
```

### Remember

> Global exception handling provides consistent and meaningful error responses across the application.

# 7. Quick Annotation Summary

| Annotation              | Main Purpose                       |
| ----------------------- | ---------------------------------- |
| `@Controller`           | Handles web requests               |
| `@RestController`       | Handles REST APIs                  |
| `@Service`              | Business logic                     |
| `@Repository`           | Database/data access               |
| `@Autowired`            | Dependency Injection               |
| `@Bean`                 | Creates a Spring-managed Bean      |
| `@Configuration`        | Defines configuration              |
| `@ExceptionHandler`     | Handles exceptions                 |
| `@ControllerAdvice`     | Common exception handling          |
| `@RestControllerAdvice` | Common REST API exception handling |

# 9. Interview Quick Revision

### Spring Boot

**What is Spring Boot?**

Spring Boot is a Java framework built on Spring that simplifies the development of production-ready applications and REST APIs.

### Architecture

**What is the basic Spring Boot architecture?**

```text
Controller
    ↓
Service
    ↓
Repository
    ↓
Database
```

### Dependency Injection

**What is DI?**

Dependency Injection means providing required dependencies to a class instead of the class creating them itself.

### Bean

**What is a Bean?**

A Bean is an object managed by the Spring Container.

### Controller

**What does Controller do?**

It handles HTTP requests and responses.

### Service

**What does Service do?**

It contains business logic.

### Repository

**What does Repository do?**

It handles database-related operations.

### Configuration

**Where can Spring Boot configuration be stored?**

Commonly in:

```text
application.properties
application.yml
```

### Logging

**Why do we use logging?**

To understand application activity, debugging information, warnings, and errors.

### Monitoring

**Why do we use monitoring?**

To check application health and performance.

To handle errors properly and return meaningful responses to clients.
