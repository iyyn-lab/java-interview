# Spring Boot Configuration

Spring Boot applications need configuration values.

Examples:

```text
Server Port
Database URL
Database Username
Database Password
External API URL
Logging Level
```

These can commonly be stored in:

```text
application.properties
```

or:

```text
application.yml
```

---

## application.properties

Example:

```properties
server.port=8080

spring.datasource.url=jdbc:postgresql://localhost:5432/mydb
spring.datasource.username=postgres
spring.datasource.password=password
```

The application can use these values instead of hardcoding them in Java code.

---

## application.yml

The same type of configuration can also be written using YAML.

```yaml
server:
  port: 8080

spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/mydb
    username: postgres
    password: password
```

Both approaches are commonly used.

---



## Why Configuration?

Instead of writing:

```java
String url = "http://localhost:3000";
```

we can keep it in configuration:

```properties
app.frontend-url=http://localhost:3000
```

This makes it easier to change values between environments.

```text
Development
     ↓
Configuration

Testing
     ↓
Configuration

Production
     ↓
Configuration
```

---



## Accessing Configuration in Java

Spring Boot configuration values can be accessed inside Java classes.

One simple way is using `@Value`.

Example:

```java
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    @Value("${app.frontend-url}")
    private String frontendUrl;

    public void printUrl() {
        System.out.println(frontendUrl);
    }
}
```

Configuration:

```properties
app.frontend-url=http://localhost:3000
```

Spring reads the value and injects it into `frontendUrl`.

```text
application.properties
        ↓
app.frontend-url
        ↓
@Value
        ↓
Java class
```

## Environment Variables

Sensitive configuration values such as passwords should generally not be hardcoded in the application configuration.

For example:

```text
Database Password
API Keys
Secret Keys
```

These can be provided using environment variables.

Example:

```properties
spring.datasource.password=${DB_PASSWORD}
```

Then the environment can provide:

```text
DB_PASSWORD=secret-password
```

This helps keep sensitive values outside the source code.

---



## Profiles

Spring Boot supports different configurations for different environments.

Common environments:

```text
Development
Testing
Production
```

Example:

```text
application.properties
application-dev.properties
application-test.properties
application-prod.properties
```

For example:

```properties
# application-dev.properties

server.port=8080
```

```properties
# application-prod.properties

server.port=80
```

The active profile can be configured using:

```properties
spring.profiles.active=dev
```

This allows the application to use environment-specific configuration.

---



## Configuration Flow

```text
Spring Boot Application
        ↓
Configuration Files
        ↓
application.properties
or
application.yml
        ↓
Environment-specific values
        ↓
Java Application
```

For different environments:

```text
Development
      ↓
application-dev.properties

Testing
      ↓
application-test.properties

Production
      ↓
application-prod.properties
```

---



### Remember

> Configuration allows application settings to be managed outside the main business logic.

> Use environment variables for sensitive values and profiles for environment-specific configuration.
