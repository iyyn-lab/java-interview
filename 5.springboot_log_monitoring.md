# 1. What is Logging?

**Logging** means recording information about what is happening inside the application.

For example:

```text
Application started
User logged in
Product created
Database connection failed
API request failed
```

Logs are useful for:

- Debugging problems
- Tracking application activity
- Finding errors
- Understanding application behavior

---

# 2. Log Levels

Spring Boot supports common logging levels:

```text
TRACE
DEBUG
INFO
WARN
ERROR
```

Simple meaning:


| Level | Meaning                        |
| ----- | ------------------------------ |
| TRACE | Very detailed information      |
| DEBUG | Debugging information          |
| INFO  | Normal application information |
| WARN  | Something may need attention   |
| ERROR | Something failed               |


For normal application messages, `INFO` is commonly used.

---

# 3. Simple Logging Example

Spring Boot provides logging support through its default logging setup.

Example:

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    private static final Logger log =
            LoggerFactory.getLogger(ProductService.class);

    public void createProduct() {
        log.info("Creating product");

        // Business logic

        log.info("Product created successfully");
    }
}
```

Example output:

```text
INFO  Creating product
INFO  Product created successfully
```

---

# 4. Logging Errors

Use `ERROR` when something fails.

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    private static final Logger log =
            LoggerFactory.getLogger(ProductService.class);

    public void createProduct() {

        try {
            // Some operation
            log.info("Creating product");

        } catch (Exception exception) {
            log.error("Failed to create product", exception);
        }
    }
}
```

The exception is also logged, which helps developers understand the problem.

---

# 5. Logging With Variables

We can include values in logs.

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;

@Service
public class ProductService {

    private static final Logger log =
            LoggerFactory.getLogger(ProductService.class);

    public void getProduct(Long productId) {

        log.info("Fetching product with id: {}", productId);
    }
}
```

If `productId` is `10`:

```text
Fetching product with id: 10
```

`{}` is used as a placeholder for values.

---

# 6. Configuration for Logging

Logging levels can be configured in:

```text
application.properties
```

Example:

```properties
logging.level.root=INFO
logging.level.com.example=DEBUG
```

This means:

```text
Root application → INFO

com.example package → DEBUG
```

This is useful when we want more detailed logs for a specific part of the application.

# 7. What is Monitoring?

**Monitoring** means checking the health, performance, and status of an application.

We may monitor:

```text
Application Health
CPU Usage
Memory Usage
API Requests
Response Time
Errors
Database Health
```

Simple difference:

```text
Logging
   ↓
"What happened?"

Monitoring
   ↓
"Is the application healthy?"
```

---

# 8. Spring Boot Actuator

**Spring Boot Actuator** provides endpoints for monitoring and managing a Spring Boot application.

One commonly used endpoint is:

```text
/actuator/health
```

Example:

```text
GET /actuator/health
```

Response:

```json
{
  "status": "UP"
}
```

`UP` means the application is currently healthy according to the configured health checks.

---

# 9. Actuator Dependency

In a Maven project, we can add Spring Boot Actuator:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

Then we can configure which endpoints should be exposed.

Example:

```properties
management.endpoints.web.exposure.include=health,info
```

Now:

```text
/actuator/health
/actuator/info
```

can be accessed.

---

# 10. Health Monitoring

The health endpoint can provide information about application dependencies.

For example:

```text
Application
    ↓
Database
    ↓
Database available?
    ↓
Health Status
```

If everything is healthy:

```json
{
  "status": "UP"
}
```

If an important dependency has a problem, the health status can indicate that the application or dependency is not healthy.

---

# 11. Logging vs Monitoring


| Logging                    | Monitoring                     |
| -------------------------- | ------------------------------ |
| Records application events | Checks application health      |
| Helps debugging            | Helps identify system problems |
| Shows what happened        | Shows current status/metrics   |
| Example: Product created   | Example: Application is UP     |


Simple example:

```text
Log:
"Database connection failed"

Monitoring:
Database health = DOWN
```

Both are useful together.

---

# 12. Simple Production Flow

```text
Spring Boot Application
          │
          ├── Logging
          │      ↓
          │   Logs
          │
          └── Monitoring
                 ↓
              Actuator
                 ↓
          Health / Metrics
```

In a production environment, logs and monitoring information can also be collected by monitoring/logging systems.

Examples:

```text
Application
     ↓
Logs
     ↓
Centralized Logging System
```
