# Request Validation in Spring Boot (Java 11)

## What is Request Validation?

Request Validation is the process of checking whether the data sent by the client is valid before processing it.

### Why Do We Need Validation?

Without validation, users can send:

* Empty values
* Invalid email addresses
* Negative prices
* Incorrect phone numbers
* Missing required fields

Validation helps ensure that only valid data enters the application.

---

## Real-Life Example

Imagine an e-commerce application where a user creates an account.

The API expects:

```json
{
  "name": "John",
  "email": "john@gmail.com",
  "age": 25
}
```

### Valid Request

```json
{
  "name": "John",
  "email": "john@gmail.com",
  "age": 25
}
```

The request is accepted.

### Invalid Request

```json
{
  "name": "",
  "email": "abc",
  "age": -5
}
```

Problems:

* Name is empty
* Email format is invalid
* Age is negative

The request should be rejected.

# Common Validation Annotations

Spring Boot uses Bean Validation annotations.

## @NotNull

Field cannot be null.

```java
@NotNull
private String name;
```

### Valid

```json
{
  "name": "John"
}
```

### Invalid

```json
{
  "name": null
}
```

---

## @NotBlank

Field cannot be:

* null
* empty
* spaces only

```java
@NotBlank
private String name;
```

### Invalid

```json
{
  "name": ""
}
```

```json
{
  "name": "   "
}
```

---

## @NotEmpty

Used for:

* String
* List
* Set
* Array

Cannot be empty.

```java
@NotEmpty
private List<String> skills;
```

### Invalid

```json
{
  "skills": []
}
```

---

## @Size

Checks minimum and maximum length.

```java
@Size(min = 3, max = 20)
private String username;
```

### Valid

```json
{
  "username": "sakthi"
}
```

### Invalid

```json
{
  "username": "ab"
}
```

---

## @Email

Validates email format.

```java
@Email
private String email;
```

### Valid

```json
{
  "email": "user@gmail.com"
}
```

### Invalid

```json
{
  "email": "abc"
}
```

---

## @Min

Minimum value allowed.

```java
@Min(18)
private Integer age;
```

### Valid

```json
{
  "age": 20
}
```

### Invalid

```json
{
  "age": 15
}
```

---

## @Max

Maximum value allowed.

```java
@Max(100)
private Integer age;
```

### Invalid

```json
{
  "age": 120
}
```

---

## @Pattern

Used for custom validation using Regular Expressions.

Example: 10-digit mobile number.

```java
@Pattern(regexp = "^[0-9]{10}$")
private String mobileNumber;
```

### Valid

```json
{
  "mobileNumber": "9876543210"
}
```

### Invalid

```json
{
  "mobileNumber": "123"
}
```

# DTO with Validation

```java
import jakarta.validation.constraints.*;

public class UserRequest {

    @NotBlank
    private String name;

    @Email
    private String email;

    @Min(18)
    private Integer age;

    // Getters and Setters
}
```

# Using @Valid in Controller

Spring performs validation when `@Valid` is used.

```java
@PostMapping("/users")
public ResponseEntity<String> createUser(
        @Valid @RequestBody UserRequest request) {

    return ResponseEntity.ok("User Created");
}
```

### How It Works

```text
Request Body
      |
      v
@RequestBody

      v
@Valid
      |

Validation Rules
      |
  +---+---+
  |       |
Pass    Fail
  |       |

Logic
```

# Validation Error Response

If validation fails, Spring automatically returns an error.

Example request:

```json
{
  "name": "",
  "email": "abc",
  "age": 10
}
```

Possible response:

```json
{
  "timestamp": "2026-09-16T10:00:00",
  "status": 400,
  "error": "Bad Request"
}
```

---

# Custom Error Messages

Instead of default messages, you can provide your own.

```java
@NotBlank(message = "Name is required")
private String name;

@Email(message = "Enter a valid email")
private String email;

@Min(value = 18, message = "Age must be at least 18")
private Integer age;
```

---

# Global Exception Handling

Use `@RestControllerAdvice` to return clean validation errors.

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<String> handleValidationException(
            MethodArgumentNotValidException ex) {

        return ResponseEntity.badRequest()
                .body("Validation Failed");
    }
}
```

# Best Practices

* Always validate user input.
* Use DTOs instead of entity classes for requests.
* Use `@Valid` in controllers.
* Provide meaningful error messages.
* Use global exception handling for consistent responses.
* Never trust client input directly.

# Summary

Request Validation ensures that incoming API data is correct before processing.

Common annotations:

| Annotation  | Purpose                                 |
| ----------- | --------------------------------------- |
| `@NotNull`  | Value cannot be null                    |
| `@NotBlank` | String cannot be null, empty, or spaces |
| `@NotEmpty` | Collection/String cannot be empty       |
| `@Size`     | Minimum and maximum length              |
| `@Email`    | Valid email format                      |
| `@Min`      | Minimum value                           |
| `@Max`      | Maximum value                           |
| `@Pattern`  | Custom validation rule                  |

In Spring Boot, validation is usually implemented using:

1. Validation annotations in DTOs
2. `@Valid` in Controller methods
3. Global Exception Handling for validation errors

This helps build secure, reliable, and user-friendly APIs.
